# Singleton

## Q. 싱글톤 패턴이란 무엇인가요?

### 답변
싱글톤 패턴은 특정 클래스의 인스턴스를 단 하나만 생성하도록 보장하고, 어디서든 동일한 인스턴스에 접근할 수 있게 하는 디자인 패턴입니다.

구현 방식은 생성자를 private으로 막고, static 필드에 인스턴스를 저장한 뒤 `getInstance()`로만 접근하게 합니다. 주로 DB 커넥션 풀처럼 생성 비용이 크거나 공유 자원이 필요한 경우에 사용합니다. 단, private 생성자로 인해 테스트 시 Mock 대체가 어렵고, 인스턴스를 공유하는 구조 특성상 stateful하게 설계하면 멀티스레드 환경에서 동시성 문제가 발생할 수 있습니다.

실무에서는 Spring이 Bean을 기본적으로 싱글톤으로 관리하면서 DI로 주입해줍니다. 이를 통해 싱글톤의 장점은 유지하면서, 결합도 문제와 테스트 어려움을 함께 해결합니다. 단, Spring Bean도 반드시 stateless하게 설계해야 합니다.

### 꼬리질문
- Spring Bean은 왜 기본적으로 싱글톤인가요?
- 싱글톤 패턴과 static 클래스의 차이는 무엇인가요?
- 싱글톤 Bean이 stateful하면 어떤 문제가 발생하나요?
- private 생성자가 테스트를 어렵게 만드는 이유는 무엇인가요?
- ThreadLocal은 언제 사용하고 어떤 점을 주의해야 하나요?
