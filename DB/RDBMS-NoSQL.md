# RDBMS와 NoSQL

## Q. RDBMS와 NoSQL의 차이는 무엇인가요?

### 답변
RDBMS는 데이터를 정해진 스키마의 테이블에 저장하고 관계를 외래키로 표현하는 관계형 데이터베이스이고, NoSQL은 고정된 스키마 없이 유연한 구조로 데이터를 저장하는 비관계형 데이터베이스입니다.

RDBMS는 데이터를 여러 테이블로 정규화해서 중복을 줄이는 대신, 조회할 때 JOIN으로 테이블을 다시 합쳐야 합니다.
반면 NoSQL은 함께 조회될 데이터를 애초에 하나의 문서나 로우에 묶어서 저장하기 때문에 JOIN 없이 바로 조회할 수 있고, 이 덕분에 대용량 데이터에서도 빠른 조회 성능을 낼 수 있습니다.
또한 스키마가 고정되어 있지 않아 컬럼 구조가 자주 바뀌는 데이터를 다룰 때 유연하게 대응할 수 있습니다.

실무에서는 정합성이 중요한 결제나 주문 데이터는 RDBMS로, 실시간 채팅 로그나 세션 캐시처럼 확장성과 조회 속도가 중요한 데이터는 NoSQL로 나눠서 함께 사용하는 경우가 많습니다.
NoSQL은 Redis 같은 Key-Value, MongoDB 같은 Document 등 저장 구조에 따라 여러 종류로 나뉩니다.

### 꼬리질문

**Q. NoSQL은 왜 조회 속도가 빠른가요?**

A. RDBMS는 정규화로 데이터를 여러 테이블에 나눠 저장해서 조회 시 JOIN 연산이 필요한데, JOIN은 테이블 간 매칭 작업이라 비용이 큽니다.
NoSQL은 함께 쓰일 데이터를 하나의 문서나 로우에 미리 합쳐서(비정규화) 저장하기 때문에 JOIN 없이 한 번의 조회로 데이터를 가져올 수 있습니다.

**Q. NoSQL에도 종류가 있나요?**

A. 네, 저장 구조에 따라 크게 4가지로 나뉩니다.
Key-Value 형태로 값을 저장하는 Redis, JSON과 비슷한 문서 단위로 저장하는 MongoDB, 대용량 쓰기에 유리한 Column-family 방식의 Cassandra, 노드와 관계 중심으로 저장하는 Graph 방식의 Neo4j가 있습니다.

**Q. NoSQL은 트랜잭션이나 데이터 정합성을 포기하는 건가요?**

A. RDBMS만큼 엄격한 ACID를 보장하지는 않고, 최종적으로 데이터가 일치하면 된다는 최종 일관성(Eventual Consistency)을 따르는 경우가 많습니다.
그래서 강한 정합성이 필요한 결제 데이터보다는, 약간의 지연된 일관성을 허용해도 되는 데이터에 더 적합합니다.

**Q. 스키마가 없다는 게 정확히 무슨 의미인가요?**

A. RDBMS는 테이블을 만들 때 컬럼과 타입을 미리 정의해야 하고, 이후 데이터는 그 구조를 반드시 따라야 합니다.
NoSQL은 이런 제약이 없어서 같은 컬렉션 안에도 문서마다 다른 필드를 가질 수 있고, 그만큼 데이터 구조가 자주 바뀌는 서비스 초기 단계에 유연하게 대응할 수 있습니다.
