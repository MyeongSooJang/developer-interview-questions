# Lock

## Q. DB Lock이란 무엇이며, 어떤 종류가 있나요?

### 답변
DB Lock은 여러 트랜잭션이 동시에 같은 데이터에 접근할 때 정합성을 보장하기 위해 데이터 접근 권한을 제어하는 메커니즘입니다.

Lock은 크게 공유 락과 베타 락으로 나뉩니다.
공유 락(Shared Lock)은 읽기 시 걸리며 여러 트랜잭션이 동시에 보유할 수 있습니다.
반면 베타 락(Exclusive Lock)은 쓰기 시 걸리며 단 하나의 트랜잭션만 점유할 수 있고, 다른 트랜잭션의 읽기와 쓰기를 모두 차단합니다.

JPA에서는 이를 낙관적 락과 비관적 락 전략으로 제어할 수 있습니다.
낙관적 락은 `@Version` 컬럼으로 충돌을 감지하고, 비관적 락은 `SELECT FOR UPDATE`로 DB 락을 선점합니다.
충돌이 드문 상황에는 낙관적 락이, 충돌이 잦은 상황에는 비관적 락이 적합합니다.

### 꼬리질문

**Q. 데드락이란 무엇이며 어떻게 방지하나요?**

A. 두 트랜잭션이 서로 상대방이 점유한 락을 기다리며 무한 대기 상태에 빠지는 것입니다.
DB는 데드락을 감지하면 한 트랜잭션을 강제 롤백해 해소합니다.
코드 레벨에서는 여러 자원에 락을 걸 때 항상 동일한 순서로 획득하도록 통일하면 예방할 수 있습니다.

**Q. 낙관적 락과 비관적 락의 차이는 무엇인가요?**

A. 낙관적 락은 충돌이 드물다고 가정하고 DB 락 없이 `@Version` 컬럼으로 충돌을 감지하며, 충돌 시 `OptimisticLockException`이 발생합니다.
비관적 락은 충돌이 자주 발생한다고 가정하고 `SELECT FOR UPDATE`로 트랜잭션 시작 시 락을 선점해 다른 트랜잭션을 대기시킵니다.
따라서 조회가 많고 충돌이 드문 경우에는 낙관적 락이, 동시 수정 빈도가 높은 경우에는 비관적 락이 적합합니다.
