# 인덱스

## Q. 인덱스(Index)란 무엇인가요? 어떤 경우에 인덱스를 사용해야 할까요?

### 답변
인덱스는 특정 컬럼의 값을 정렬된 별도 자료구조(B-Tree)로 저장해, 테이블 전체를 탐색하지 않고도 원하는 행을 빠르게 찾을 수 있게 해주는 DB 성능 최적화 기법입니다.

인덱스가 없으면 WHERE 조건으로 조회할 때 테이블을 처음부터 끝까지 순차 탐색(Full Table Scan)해야 합니다.
B-Tree 인덱스는 컬럼 값을 정렬된 트리 구조로 유지하고, 각 값마다 실제 행을 가리키는 포인터를 가지고 있어 루트에서 리프 노드까지 O(log n)으로 데이터를 찾을 수 있습니다.

인덱스는 WHERE, JOIN, ORDER BY에 자주 등장하고 카디널리티가 높은 컬럼(이메일, 주문번호처럼 중복도가 낮은 컬럼)에 거는 것이 효과적입니다.
반면 INSERT·UPDATE·DELETE 시 인덱스 자료구조도 함께 갱신해야 하므로, 쓰기가 잦은 테이블에 인덱스를 과도하게 생성하면 오히려 성능이 저하될 수 있습니다.

### 꼬리질문

**Q. B-Tree 인덱스는 어떤 구조인가요?**

A. B-Tree는 모든 리프 노드가 같은 깊이에 위치하는 균형 트리입니다.
내부 노드는 키 값 범위를 기준으로 자식 노드를 분기하고, 리프 노드에는 실제 컬럼 값과 행 포인터가 정렬된 상태로 저장됩니다.
덕분에 등치 조회뿐 아니라 범위 조회(BETWEEN, >, <)에도 효과적입니다.

**Q. 카디널리티가 낮은 컬럼에 인덱스를 걸면 왜 비효율적인가요?**

A. 카디널리티가 낮은 컬럼은 성별처럼 값의 종류가 몇 가지 안 돼, 인덱스로 걸러도 전체 행의 상당 부분이 결과에 포함됩니다.
이 경우 DB 옵티마이저가 인덱스를 타는 것보다 Full Table Scan이 더 빠르다고 판단해 인덱스를 무시하기도 합니다.

**Q. 복합 인덱스(Composite Index)란 무엇인가요?**

A. 두 개 이상의 컬럼을 묶어 하나의 인덱스로 만든 것입니다.
컬럼 순서가 중요한데, 인덱스의 첫 번째 컬럼이 WHERE 조건에 포함되어야 인덱스를 탈 수 있습니다.
예를 들어 (user_id, created_at) 인덱스는 user_id 조건 없이 created_at만으로 조회하면 인덱스를 활용하지 못합니다.
