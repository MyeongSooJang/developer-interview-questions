# 자바 컴파일 과정

## Q. 자바가 컴파일되는 과정을 설명해주세요.

### 답변
자바는 소스코드 → 바이트코드 → 기계어 실행의 2단계 컴파일 과정을 거칩니다.

먼저 javac가 .java 소스코드를 플랫폼 독립적인 바이트코드(.class)로 변환합니다.
그 다음 JVM의 Class Loader가 바이트코드를 동적으로 로딩해 Runtime Data Area에 올립니다.
마지막으로 Execution Engine이 인터프리터(한 줄씩 실행) 또는 JIT 컴파일러(전체를 기계어로 변환 후 실행)로 처리합니다.

이 구조 덕분에 Write Once, Run Anywhere가 가능하고, JIT 컴파일러는 자주 실행되는 코드를 캐싱해 반복 실행 시 성능을 높입니다.

### 꼬리질문
- 인터프리터 방식과 JIT 컴파일러 방식의 차이는 무엇인가요?
- 바이트코드는 왜 플랫폼에 독립적인가요?

--- 

## Q. 인터프리터 방식과 JIT 컴파일러 방식의 차이는 무엇인가요?

### 답변
인터프리터는 바이트코드를 한 줄씩 읽어 실행하므로 시작은 빠르지만 반복 실행 시 느립니다.
JIT 컴파일러는 자주 실행되는 코드를 기계어로 컴파일해 캐싱하므로, 반복 실행 시 훨씬 빠릅니다.

---

## Q. 바이트코드는 왜 플랫폼에 독립적인가요?

### 답변
바이트코드는 특정 OS나 CPU에 종속되지 않는 중간 언어로, JVM이 설치된 어떤 환경에서도 실행할 수 있습니다.
각 OS별 JVM이 바이트코드를 해당 플랫폼의 기계어로 변환해주기 때문입니다.
