# 오버로딩과 오버라이딩

## Q. 오버로딩과 오버라이딩의 차이는 무엇인가요?

### 답변
오버로딩은 같은 클래스 내에서 메서드 이름은 같고 매개변수의 타입·개수·순서를 다르게 정의하는 것이고, 
오버라이딩은 부모 클래스의 메서드를 자식 클래스에서 동일한 시그니처로 재정의하는 것입니다.

오버로딩은 컴파일 타임에 결정되는 정적 다형성이고, 오버라이딩은 런타임에 실제 객체 타입 기준으로 결정되는 동적 다형성입니다.

실무에서 오버라이딩은 Spring에서 인터페이스 구현체를 교체하거나 전략 패턴을 구현할 때 핵심적으로 활용됩니다.
단, static 메서드는 오버라이딩이 불가하고, 오버라이딩 시 접근 제어자를 좁히거나 새로운 checked 예외를 추가할 수 없다는 제약이 있습니다.

### 꼬리질문
- static 메서드는 오버라이딩이 가능한가요?
- @Override 어노테이션을 생략하면 어떻게 되나요?
- 오버로딩 시 반환 타입만 다른 경우는 왜 안 되나요?
- 오버라이딩의 제약조건에 대해 설명해주세요.

---

## Q. static 메서드는 오버라이딩이 가능한가요?

### 답변
static 메서드는 런타임 객체 타입이 아닌 참조 변수의 타입을 기준으로 컴파일 타임에 결정됩니다.
따라서 자식 클래스에서 같은 이름으로 정의해도 오버라이딩이 아닌 메서드 은닉(Method Hiding)이 되며, 다형성이 적용되지 않습니다.

---

## Q. @Override 어노테이션을 생략하면 어떻게 되나요?

### 답변
어노테이션 없이도 시그니처가 일치하면 오버라이딩은 동작합니다.
다만 `@Override`를 붙이면 컴파일러가 부모 메서드 존재 여부를 검증해 오타나 시그니처 불일치를 조기에 잡아줄 수 있어, 명시적으로 붙이는 것이 권장됩니다.

---

## Q. 오버로딩 시 반환 타입만 다른 경우는 왜 안 되나요?

### 답변
메서드 호출 시 컴파일러는 반환값을 변수에 담기 전까지는 반환 타입을 기준으로 어떤 메서드를 호출할지 구별할 수 없습니다.
따라서 반환 타입만 다른 경우 호출 대상을 결정할 수 없어 컴파일 에러가 발생합니다.

---

## Q. 오버라이딩의 제약조건에 대해 설명해주세요.

### 답변
오버라이딩은 세 가지 제약조건이 있는데, 시그니처·접근 제어자·예외 선언 범위에 대한 규칙입니다.

첫째, 메서드 이름과 매개변수는 부모와 완전히 동일해야 하지만, 반환 타입은 부모 타입의 하위 타입으로 좁히는 공변 반환 타입(Covariant Return Type)은 허용됩니다.
둘째, 접근 제어자는 부모보다 좁은 범위로 변경할 수 없습니다. 예를 들어 부모가 `protected`라면 자식은 `protected` 또는 `public`만 가능합니다.
셋째, 부모 메서드보다 더 넓은 범위의 checked 예외를 선언할 수 없습니다. 부모가 `IOException`을 던진다면 자식은 그 하위인 `FileNotFoundException`은 가능하지만 `Exception`은 불가합니다.
