# equals()와 hashCode()

## Q. equals()와 hashCode()를 같이 재정의하는 이유는 무엇인가요?

### 답변
equals()는 두 객체가 논리적으로 같은지 비교하는 메서드이고, hashCode()는 객체를 식별하는 정수값인 해시코드를 반환하는 메서드입니다.
자바는 equals()로 같다고 판단되는 두 객체는 반드시 같은 hashCode()를 반환해야 한다는 규약을 정의하고 있습니다.

HashMap이나 HashSet 같은 해시 기반 자료구조는 먼저 hashCode()로 저장할 버킷 위치를 찾고, 그 버킷 안에서 equals()로 실제 값을 비교하기 때문입니다.
그래서 equals()만 오버라이드하고 hashCode()를 그대로 두면, 논리적으로 같은 객체인데도 서로 다른 해시코드를 가져 다른 버킷에 저장되고, 결국 찾을 수 없거나 중복으로 저장되는 문제가 생깁니다.

그래서 equals()를 오버라이드할 때는 반드시 hashCode()도 함께 오버라이드해야 합니다.
대표적으로 회원 객체를 HashSet에 넣어 중복을 걸러낼 때, 두 메서드를 함께 오버라이드하지 않으면 같은 회원인데도 중복으로 저장되는 버그로 이어질 수 있습니다.

### 꼬리질문

**Q. equals()만 오버라이드하고 hashCode()는 그대로 두면 어떤 문제가 생기나요?**

A. 논리적으로 같은 두 객체가 서로 다른 해시코드를 갖게 되어, HashMap에 하나를 키로 저장해도 다른 하나로는 조회가 되지 않는 문제가 발생합니다.
