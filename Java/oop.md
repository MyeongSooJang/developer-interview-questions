# OOP (객체지향 프로그래밍)

## Q. OOP란 무엇인가요?

### 답변
OOP는 프로그램을 객체(데이터 + 행동)의 집합으로 구성하고, 객체 간 메서드 호출로 상호작용하는 프로그래밍 패러다임입니다.

OOP는 추상화·캡슐화·상속·다형성의 4대 특성을 기반으로 하며, 현실 세계의 개념을 객체로 모델링해 코드의 재사용성과 유지보수성을 높입니다.
절차지향이 "어떻게 처리할 것인가"에 집중한다면, OOP는 "누가 무엇을 책임지는가"에 집중합니다.

실무에서는 Spring의 Bean 관리, 인터페이스 기반 설계 등 OOP 원칙이 프레임워크 전반에 녹아 있습니다.
특히 다형성을 활용한 전략 패턴이나 캡슐화를 통한 도메인 모델 설계에서 OOP의 장점이 두드러집니다.

## Q. OOP의 4대 특성에 대해 설명해주세요.

### 답변
OOP의 4대 특성은 추상화·캡슐화·상속·다형성이며, 각각 복잡성 감소·정보 은닉·재사용·유연성을 목적으로 합니다.

추상화는 객체의 공통 속성과 행동만 추출해 인터페이스나 추상 클래스로 표현하는 것이고, 캡슐화는 데이터와 메서드를 하나로 묶고 접근 제어자로 외부에 필요한 인터페이스만 노출하는 것입니다.
상속은 부모 클래스의 속성과 메서드를 자식 클래스가 물려받아 코드 재사용성을 높이는 것이고, 다형성은 하나의 타입으로 여러 구현을 다룰 수 있는 것으로 오버로딩과 오버라이딩이 대표적인 예입니다.

실무에서는 캡슐화로 도메인 객체의 내부 상태를 보호하고, 다형성으로 구현체를 유연하게 교체하는 방식을 자주 활용합니다.
다만 상속은 부모-자식 간 결합도가 높아져 변경에 취약할 수 있어, 상속보다 조합(Composition)을 우선하는 것이 권장됩니다.

## Q. 절차지향과 객체지향의 차이는 무엇인가요?

### 답변
절차지향은 데이터와 함수를 분리해 순서대로 처리하는 방식이고, 객체지향은 데이터와 행동을 객체로 묶어 객체 간 협력으로 문제를 해결하는 방식입니다.
절차지향은 실행 흐름이 명확해 성능이 유리하지만, 요구사항 변경 시 함수와 데이터가 곳곳에 퍼져 있어 수정 범위가 넓어집니다.
반면 객체지향은 변경이 생기면 해당 객체 내부만 수정하면 되어 유지보수에 유리합니다.

---

## Q. 캡슐화와 추상화의 차이는 무엇인가요?

### 답변
캡슐화는 데이터와 메서드를 하나로 묶고 접근 제어자로 내부 구현을 숨기는 것이고, 추상화는 복잡한 내부 로직은 감추고 사용자에게 필요한 인터페이스만 드러내는 것입니다.
캡슐화가 "어떻게 숨길 것인가"라면, 추상화는 "무엇을 보여줄 것인가"에 초점을 둡니다.

---

## Q. 상속보다 조합(Composition)을 선호하는 이유는 무엇인가요?

### 답변
상속은 부모 클래스의 구현에 자식이 강하게 결합되어, 부모 변경 시 자식 클래스가 의도치 않게 영향을 받는 취약한 기반 클래스 문제가 발생할 수 있습니다.
반면 조합은 필요한 기능을 가진 객체를 내부에 포함해 위임하는 방식으로, 결합도를 낮추고 런타임에 동작을 유연하게 교체할 수 있습니다.
실무에서는 "상속은 IS-A 관계가 명확할 때만, 그 외에는 조합"을 원칙으로 삼습니다.
